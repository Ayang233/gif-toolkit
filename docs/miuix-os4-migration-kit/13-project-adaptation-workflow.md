# 13 · 从 L0 到 L6：适配工作流与成熟度分级

> 本篇把前面所有内容串成**可执行流程**：9 个阶段（0～8）+ 7 个成熟度等级（L0～L6）。
> 两条铁律：
> **① 任一阶段存在阻断性问题，不得进入下一阶段。② 未验证的项不能算完成。**

---

## 1. 阶段与等级的对应

```
阶段 0 项目扫描 ──────────────→ 产出基线报告（不评级）
阶段 1 可行性判断 ────────────→ L0 确认（或不适用）
阶段 2 MIUIX 基础接入 ────────→ L1 基础接入
阶段 3 全项目 OS4 UI 迁移 ────→ L2 组件迁移
阶段 4 自适应与导航 ──────────→ L3 全项目 OS4 适配
阶段 5 Glass 接入 ────────────→ L4 Glass 架构接入
阶段 6 全项目 Glass 适配 ─────→ L5 Glass 全项目适配
阶段 7 全量测试 ──────────────→ L6 的一半证据
阶段 8 验收与回滚 ────────────→ L6 完整验收
```

---

## 2. 阶段 0 · 项目扫描（只读，不改代码）

| 项 | 内容 |
|---|---|
| 输入 | 项目源码 |
| 动作 | 按 [01](01-project-assessment.md) §1 的 9 类扫描；跑 [01](01-project-assessment.md) §5 的 grep |
| 输出 | 项目基线报告（模板 [14](14-new-project-audit-template.md)） |
| 完成判据 | 报告里 9 类都有事实，且每条有 `路径:行号` |
| 禁止 | 修改任何文件；"顺手升个版本" |

**产物**：`docs/adaptation/00-baseline.md`

## 3. 阶段 1 · 可行性判断

| 项 | 内容 |
|---|---|
| 输入 | 基线报告 |
| 动作 | 走 [01](01-project-assessment.md) §2 的决策树；填 §3 可行性矩阵；列前置条件 |
| 输出 | **明确结论**：能接 / 需先迁移 / 不能接（附阻断条件） |
| 完成判据 | 前置条件全部有"已满足/需解决"的判定 |

**阻断条件**（任一成立就停下，写清楚再决定）：

| 阻断 | 说明 |
|---|---|
| 非 Kotlin / 非 Compose | 需先迁移，成本另评估 |
| minSdk < 24 | MIUIX 模块最低 24 |
| compileSdk < MIUIX 要求（可能带 minor） | AGP 配置期直接失败 |
| Kotlin / CMP 版本低于 MIUIX | 必须先升 |
| 存在 material3 且不能移除 | 设计体系冲突，需先决策 |
| 构建本身跑不通 | 先修构建 |

**产物**：`docs/adaptation/01-feasibility.md`

> 这一步的产出是**结论**，不是"再看看"。如果结论是"需先迁移"，那么阶段 2 之前要先做一次
> Compose 迁移（那是另一个项目，不在本流程内）。

## 4. 阶段 2 · MIUIX 基础接入（→ L1）

| 项 | 内容 |
|---|---|
| 动作 | ① 依赖（[02](02-version-and-dependencies.md)）② 主题装配（[03](03-os4-theme-system.md) §1）③ ColorScheme/Typography 收敛（[03](03-os4-theme-system.md) §2/§6）④ 基础组件换到 `Scaffold`/`Card`/`Text` ⑤ Preference 换到 `SwitchPreference` 等 |
| 输出 | 能跑、能看、颜色正确、有设置页 |
| 完成判据 | 见下 |

**L1 门槛**：

- [ ] `./gradlew :app:assembleDebug` 通过
- [ ] `MiuixTheme` 是唯一主题来源（全项目 grep `MaterialTheme` 零命中）
- [ ] 四种配色（静态/Monet × 明/暗）都能跑起来且页面与卡片有层次
- [ ] 至少一个页面完整用 MIUIX 组件
- [ ] 没有 `Color(0x…)` 散落在页面里（主题文件除外）

**产物**：`docs/adaptation/02-base-integration.md` + 截图

## 5. 阶段 3 · 全项目 OS4 UI 迁移（→ L2 / L3）

| 项 | 内容 |
|---|---|
| 动作 | 按 [04](04-component-mapping.md) 逐页替换；容器统一；卡片/行/按钮/输入/弹层 |
| 输出 | 所有页面用同一套骨架 |
| 完成判据 | L2：主要页面完成；L3：**全部适用页面**完成且经过审计 |

### 5.1 先做一个"试点页"

不要一上来改 App 骨架。选**一个设置类列表页**（结构最标准、状态最少、最容易回滚）做试点：

选试点页的标准：

- 有一个 `Scaffold` + 顶栏 + 若干卡片/行。
- 没有复杂动画、没有视频/画布、没有大量弹层。
- 有返回路径，可以反复进出。

试点页要一次性跑通：容器、顶栏、卡片、行、一个弹层、四配色、返回。
跑通后再推广 —— 后面 80% 的页面都是同一套复写。

**反例**：从主页（有导航 + Pager + 悬浮按钮 + 弹层）开始。一处结构错，所有页面跟着错。

**L2 门槛**（主要页面）：

- [ ] 一级页面全部迁移
- [ ] 顶栏/导航/卡片/按钮/设置行/弹层六类都有代表页面完成
- [ ] 无 material3
- [ ] 功能没有回退（每个入口都能点、能完成原流程）

**L3 门槛**（全项目）：

- [ ] 页面覆盖率 100%（分母含排除项与理由）
- [ ] 组件覆盖率 ≥ 95%（剩余 5% 必须有"保留自定义"的书面理由）
- [ ] 每个页面都有"四种配色"截图
- [ ] 每个弹层都验证过位置与关闭

> **L2 与 L3 的区别不是"组件用了多少"，而是"分母是否闭合"**：
> L2 允许"还有页面没动"，L3 要求"每个页面都有结论"。

**产物**：`docs/adaptation/03-os4-migration.md` + 覆盖表

## 7. 阶段 5 · Glass 接入（→ L4）

**顺序不能颠倒**：先根布局与录制层，再页面局部 Glass，最后全局弹层。

| 步骤 | 动作 | 完成判据 |
|---|---|---|
| 5.1 | 建**唯一决策点** `LocalGlassEnabled = 用户开关 && isGlassSupported()` | 页面里没有第二处能力判断 |
| 5.2 | 建**一级页整屏录制层**（录在分页容器外） | 底栏/侧栏/弹层都能采到它 |
| 5.3 | 建**页面正文录制层**（先 `drawRect(页面底色)`） | 顶栏/卡片能采到它 |
| 5.4 | 接**顶栏**（`GlassTopAppBar` + `contentModifier` + band 参数） | 顶栏有玻璃、无硬边 |
| 5.5 | 接**底栏/侧栏** | 是录制层兄弟、`visible=false` 未使用 |
| 5.6 | 接**页面局部**（玻璃卡等） | `backdrop == null` 时有回退 |
| 5.7 | 接**全局弹层**（Dialog/Sheet/Dropdown） | 宿主正确、坐标正确 |
| 5.8 | 处理**空采样**页面（叠加采样源） | 任何滚动位置都有像素 |

**L4 门槛**：

- [ ] 只有一个玻璃决策点
- [ ] 两类录制层都存在，且消费者都是兄弟
- [ ] 顶栏 / 底栏 / 侧栏 / 主要弹层四类 Glass 宿主正确
- [ ] `backdrop = null` 时全部功能仍可用（入口不消失）
- [ ] 没有 `SIGSEGV`（进出页面 20 次）

**产物**：`docs/adaptation/05-glass-architecture.md` + 结构图

## 8. 阶段 6 · 全项目 Glass 适配（→ L5）

| 动作 | 完成判据 |
|---|---|
| 逐组件按 [07](07-glass-component-guide.md) §6 的 5 问自检 | 每个 Glass 组件都有答案 |
| 逐页面按 [07](07-glass-component-guide.md) §8 判定"该不该 Glass" | 每个页面有结论（该/不该 + 理由） |
| 检查所有弹层采样源 | 无跨坐标空间 |
| 检查所有自绘组件的层级 | 无自建录制层包消费者 |
| 静态检查：录制层数量 | 同屏 ≤ 2 层整屏录制 |

**L5 门槛**：

- [ ] Glass 组件清单闭合（用了/没用都有理由）
- [ ] 所有"该 Glass"的位置都 Glass，所有"不该"的位置都没有
- [ ] 每个 Glass 位置都能回答"采样源在哪、覆盖是否完整"
- [ ] 软件渲染下的降级行为已记录

**产物**：`docs/adaptation/06-glass-adaptation.md` + 组件矩阵

## 11. 成熟度分级 L0～L6

### 11.1 定义

| 等级 | 名称 | 达成要求 |
|---|---|---|
| **L0** | 原始项目 | 尚未接入 MIUIX |
| **L1** | 基础接入 | 依赖、Theme、ColorScheme、基础环境完成；一个页面跑通 |
| **L2** | OS4 组件迁移 | **主要**页面与常用控件已迁移，功能不回退 |
| **L3** | OS4 全项目适配 | **所有适用**页面完成迁移并经过审计；导航/自适应/Insets 完成 |
| **L4** | Glass 架构接入 | 单一决策点、两类录制层、四类宿主正确；无自采样 |
| **L5** | Glass 全项目适配 | 所有适用组件完成适配与自检；该/不该 Glass 都有结论 |
| **L6** | 完整验收 | 真机 + 兼容性 + 回归 + 交付验收完成，且证据留档 |

### 11.2 分级不能只看"用了多少组件"

必须同时看 9 个维度：

| # | 维度 | 度量 | 说明 |
|---|---|---|---|
| 1 | 源码覆盖率 | `已改 UI 相关文件 / 全部 UI 相关文件` | grep 出来的清单为分母 |
| 2 | 页面覆盖率 | `已迁移页面 / 适用页面` | 排除项要写理由 |
| 3 | 组件覆盖率 | `已迁移组件 / 适用组件` | 六类：容器/顶栏/导航/卡片/行/弹层 |
| 4 | 功能完整性 | 0–2 分 | 0 有回退；1 主流程可用；2 全功能等价 |
| 5 | 视觉一致性 | 0–2 分 | 0 明显混搭；1 主要页面一致；2 全项目一致（含四配色） |
| 6 | Glass 架构正确性 | 0–2 分 | 0 有自采样/坐标错误；1 结构正确但有空采样；2 结构+覆盖都正确 |
| 7 | 运行稳定性 | 0–2 分 | 0 有闪退；1 无闪退但偶发异常；2 反复操作稳定 |
| 8 | 设备适配 | 0–2 分 | 0 只一种尺寸；1 手机+宽屏；2 含真机/圆角/手势条 |
| 9 | 测试证据 | 0–2 分 | 0 无证据；1 模拟器；2 真机 + 留档 |

**证据等级加权**（关键：未验证不算完成）：

| 证据 | 折扣 |
|---|---|
| 源码审计 | ×0.5 |
| 模拟器（硬件 GPU） | ×0.8 |
| 模拟器（软件渲染） | ×0.6（玻璃类项目记 0） |
| 真机 | ×1.0 |

也就是说：一个"源码上完全正确、只在模拟器跑过"的 Glass 项，**不能算 L5 的一部分**；
它最多贡献 L4（架构正确）而不贡献 L5（全项目适配完成）。

### 11.3 各等级的**必要条件**（全满足才算）

| 等级 | 必要条件 |
|---|---|
| L1 | 阶段 2 的 5 项门槛全过 |
| L2 | L1 + 主要页面迁移 + 功能完整性 ≥ 1 + 视觉一致性 ≥ 1 |
| L3 | L2 + 页面覆盖率 100%（含排除理由）+ 组件覆盖率 ≥ 95% + 自适应四尺寸截图 |
| L4 | L3 + Glass 架构正确性 = 2 + 运行稳定性 ≥ 1 + 只有一个决策点 |
| L5 | L4 + Glass 组件矩阵闭合 + 每个 Glass 位置 5 问有答案 + 视觉一致性 = 2 |
| L6 | L5 + 测试证据 = 2（真机留档）+ 设备适配 = 2 + 回归清单全过 + 回滚已验证 |

### 11.4 分母怎么"合理排除"

允许排除，但必须**写在报告里、有理由、可审计**：

| 类型 | 可排除 | 不可排除 |
|---|---|---|
| 页面 | 系统权限页、文件选择器、WebView 内嵌页、崩溃上报页 | "这个页面太难改" |
| 组件 | 系统分享面板、通知、悬浮窗 | "这个按钮样式不一样" |
| Glass | 系统级弹窗、相机预览、视频全屏（语义上不该玻璃） | "玻璃在模拟器上看不出来" |
| 设备 | 不支持的 API 版本（<24） | "没有真机"（→ 记 L5 未达成） |

### 11.5 评级示例（GIF 助手 1.10）

| 维度 | 判定 | 依据 |
|---|---|---|
| 源码覆盖率 | 高 | 8 个页面全部走同一骨架 |
| 页面覆盖率 | 100% | 含 `ButtonColors`（仅 debug，排除并注明） |
| 组件覆盖率 | ~100% | 组件矩阵见 [07](07-glass-component-guide.md) §7 |
| 功能完整性 | 2 | 构建通过，功能未删（但 1.10 未重跑交互 🔴） |
| 视觉一致性 | 2 | 四配色 × 多尺寸截图（模拟器） |
| Glass 架构正确性 | 2 | 单一决策点、两类录制层、四类宿主正确 |
| 运行稳定性 | 2 | 反复进出无闪退（模拟器） |
| 设备适配 | 1 | 多尺寸/多密度 ✅；真机 ❌ |
| 测试证据 | 1 | 模拟器 + 像素测量 + 探针；真机 ❌ |
| **结论** | **L5（模拟器级）** | L6 缺真机证据（`textureBlur`、玻璃观感、触觉、圆角安全区） |

> 这个例子说明为什么"分级"有用：它能诚实地表达"工程做完了，但还差真机验收"。

## 12. 阶段间的"门"（gate）清单

进入下一阶段前必须回答"是"：

| 门 | 问题 |
|---|---|
| G0→1 | 基线报告里每条事实都有源码位置吗？ |
| G1→2 | 可行性的阻断条件都解决了吗？ |
| G2→3 | 主题是唯一颜色来源吗？四种配色都能跑吗？ |
| G3→4 | 所有页面都用同一骨架了吗？功能有回退吗？ |
| G4→5 | 四种尺寸 + RTL + 大字都过了吗？ |
| G5→6 | 有自采样吗？弹层坐标对吗？`backdrop=null` 时功能还在吗？ |
| G6→7 | Glass 组件矩阵闭合了吗？该/不该都有理由吗？ |
| G7→8 | 真机证据齐了吗？未验证项都列出来了吗？ |
| G8 完成 | 回滚验证过了吗？成熟度评级有依据吗？ |

## 13. 规模与工作量参考（GIF 助手实测）

| 项 | GIF 助手 |
